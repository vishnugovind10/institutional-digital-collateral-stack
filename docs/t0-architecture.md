# T+0 Architecture

T+0 is not merely faster settlement. At sufficiently compressed windows, coordination itself becomes settlement infrastructure.

## What changes

| Surface | Longer cycles | T+0 / continuous |
|---|---|---|
| Eligibility | Batch review can absorb delays | Must be event-driven |
| Liquidity | Funding can be arranged across windows | Peak timing becomes binding |
| Authorization | Manual approvals can be refreshed | Validity and conflicts become state |
| Reconciliation | Breaks are handled after the event | Divergence blocks confidence |
| Evidence | Workpapers can be assembled later | Evidence must travel with the state |

## Thesis

At sufficiently compressed settlement windows, coordination, state agreement, liquidity timing, authorization, and evidence become first-class settlement infrastructure.
